# Интернет-магазин «Web-Larёk»

«Web-Larёk» — это интернет-магазин с товарами для веб-разработчиков, где пользователи могут просматривать товары, добавлять их в корзину и оформлять заказы. Сайт предоставляет удобный интерфейс с модальными окнами для просмотра деталей товаров, управления корзиной и выбора способа оплаты, обеспечивая полный цикл покупки с отправкой заказов на сервер.

## Архитектура приложения

Код приложения разделен на слои согласно парадигме MVP (Model-View-Presenter), которая обеспечивает четкое разделение ответственности между классами слоев Model и View. Каждый слой несет свой смысл и ответственность:

Model - слой данных, отвечает за хранение и изменение данных.  
View - слой представления, отвечает за отображение данных на странице.  
Presenter - презентер содержит основную логику приложения и отвечает за связь представления и данных.

Взаимодействие между классами обеспечивается использованием событийно-ориентированного подхода. Модели и Представления генерируют события при изменении данных или взаимодействии пользователя с приложением, а Презентер обрабатывает эти события используя методы как Моделей, так и Представлений.

### Базовый код

#### Класс Component

Является базовым классом для всех компонентов интерфейса.
Класс является дженериком и принимает в переменной `T` тип данных, которые могут быть переданы в метод `render` для отображения.

Конструктор:  
`constructor(container: HTMLElement)` - принимает ссылку на DOM элемент за отображение, которого он отвечает.

Поля класса:  
`container: HTMLElement` - поле для хранения корневого DOM элемента компонента.

Методы класса:  
`render(data?: Partial<T>): HTMLElement` - Главный метод класса. Он принимает данные, которые необходимо отобразить в интерфейсе, записывает эти данные в поля класса и возвращает ссылку на DOM-элемент. Предполагается, что в классах, которые будут наследоваться от `Component` будут реализованы сеттеры для полей с данными, которые будут вызываться в момент вызова `render` и записывать данные в необходимые DOM элементы.  
`setImage(element: HTMLImageElement, src: string, alt?: string): void` - утилитарный метод для модификации DOM-элементов `<img>`

#### Класс Api

Содержит в себе базовую логику отправки запросов.

Конструктор:  
`constructor(baseUrl: string, options: RequestInit = {})` - В конструктор передается базовый адрес сервера и опциональный объект с заголовками запросов.

Поля класса:  
`baseUrl: string` - базовый адрес сервера  
`options: RequestInit` - объект с заголовками, которые будут использованы для запросов.

Методы:  
`get(uri: string): Promise<object>` - выполняет GET запрос на переданный в параметрах ендпоинт и возвращает промис с объектом, которым ответил сервер  
`post(uri: string, data: object, method: ApiPostMethods = 'POST'): Promise<object>` - принимает объект с данными, которые будут переданы в JSON в теле запроса, и отправляет эти данные на ендпоинт переданный как параметр при вызове метода. По умолчанию выполняется `POST` запрос, но метод запроса может быть переопределен заданием третьего параметра при вызове.  
`handleResponse(response: Response): Promise<object>` - защищенный метод проверяющий ответ сервера на корректность и возвращающий объект с данными полученный от сервера или отклоненный промис, в случае некорректных данных.

#### Класс EventEmitter

Брокер событий реализует паттерн "Наблюдатель", позволяющий отправлять события и подписываться на события, происходящие в системе. Класс используется для связи слоя данных и представления.

Конструктор класса не принимает параметров.

Поля класса:  
`_events: Map<string | RegExp, Set<Function>>)` - хранит коллекцию подписок на события. Ключи коллекции - названия событий или регулярное выражение, значения - коллекция функций обработчиков, которые будут вызваны при срабатывании события.

Методы класса:  
`on<T extends object>(event: EventName, callback: (data: T) => void): void` - подписка на событие, принимает название события и функцию обработчик.  
`emit<T extends object>(event: string, data?: T): void` - инициализация события. При вызове события в метод передается название события и объект с данными, который будет использован как аргумент для вызова обработчика.  
`trigger<T extends object>(event: string, context?: Partial<T>): (data: T) => void` - возвращает функцию, при вызове которой инициализируется требуемое в параметрах событие с передачей в него данных из второго параметра.## Данные

В приложении используются две сущности, описывающие данные, — товар и покупатель.

#### Интерфейс IProduct

Описывает структуру товара, получаемого с сервера и отображаемого в каталоге и карточке товара.

Поля интерфейса:

`id: string` - уникальный идентификатор товара
`description`: string - описание товара
`image: string` - URL изображения товара
`title: string` - название товара
`category: string` - категория товара
`price: number | null` - цена товара (null, если товар бесценен)

#### Интерфейс IBuyer

Описывает данные покупателя, которые тот вводит при оформлении заказа.

Поля интерфейса:

`payment: TPayment` - способ оплаты: картой или наличными
`email: string` - электронная почта покупателя
`phone: string` - номер телефона покупателя
`address: string` - адрес доставки

#### Тип TPayment

Описывает тип оплаты. Может быть онлайн `card`, при получении `cash` или пустым значением.

`type TPayment = "card" | "cash" | ""`

#### Тип TErrors

Объект для хранения ошибок валидации полей покупателя. Ключами могут быть только поля IBuyer, значениями - текстовые сообщения об ошибках. Присутствуют только поля с ошибками.

`export type TErrors = Partial<Record<keyof IBuyer, string>>`

#### Интерфейс IResponseData

Описывает объект, который должен прийти от сервера.

Поля интерфейса:

`total: number;` - количество товаров.
`items: IProduct[];` - массив товаров.

#### Интерфейс IOrderData

Описывает объект, который должен отправляться на сервер. Расширяет интерфейс IBuyer.

Добавленные поля интерфейса:

`total: number;` - стоимость купленных товаров.
`items: string[];` - массив с id товаров.

#### Интерфейс IOrderResponse

Описывает структуру ответа сервера после успешного оформления заказа. Содержит id созданного заказа и итоговую сумму total.

`id: string;` - id заказа.
`total: number;` - итоговая сумма.

### Модели данных

#### Класс Catalog

Модель каталога товаров. Отвечает за хранение полного списка товаров приложения, а также за хранение товара, выбранного пользователем для подробного просмотра.

Конструктор:
`constructor()` — конструктор не принимает параметров, инициализирует пустой массив товаров и устанавливает выбранный товар в `null`.

Поля класса:
`items: IProduct[]` — массив всех товаров каталога, доступных для покупки в приложении.
`selectedItem: IProduct | null` — товар, выбранный пользователем для подробного отображения. По умолчанию `null`.

Методы класса:
`setItems(items: IProduct[]): void` — принимает массив товаров типа `IProduct[]` и сохраняет его в поле `items`.
`getItems(): IProduct[]` — возвращает массив всех товаров каталога типа `IProduct[]`.
`getItemById(id: string): IProduct | undefined` — принимает идентификатор товара типа `string`, возвращает найденный товар типа `IProduct` или `undefined`, если товар не найден.
`setSelectedItem(item: IProduct): void` — принимает объект товара типа `IProduct` и сохраняет его в поле `selectedItem` для подробного отображения.
`getSelectedItem(): IProduct | null` — возвращает товар, сохранённый для подробного отображения, типа `IProduct` или `null`, если ни один товар не выбран.

#### Класс Cart

Модель корзины покупок. Отвечает за хранение товаров, выбранных пользователем для покупки, и за операции над ними.

Конструктор:
`constructor()` — конструктор не принимает параметров, инициализирует пустой массив товаров корзины.

Поля класса:
`items: IProduct[]` — массив товаров, добавленных пользователем в корзину.

Методы класса:
`getItems(): IProduct[]` — возвращает массив товаров, находящихся в корзине, типа `IProduct[]`.
`addItem(item: IProduct): void` — принимает объект товара типа `IProduct` и добавляет его в массив корзины.
`removeItem(item: IProduct): void` — принимает объект товара типа `IProduct` и удаляет его из массива корзины.
`clearCart(): void` — очищает корзину, удаляя все товары из массива `items`.
`getTotal(): number` — возвращает суммарную стоимость всех товаров в корзине типа `number`.
`getCount(): number` — возвращает количество товаров в корзине типа `number`.
`hasItem(id: string): boolean` — принимает идентификатор товара типа `string` и возвращает `boolean`: `true`, если товар с таким `id` находится в корзине, `false` — если нет.

#### Класс Buyer

Модель данных покупателя. Отвечает за хранение, обновление, валидацию и очистку данных, которые покупатель вводит при оформлении заказа.

Конструктор:
`constructor()` — конструктор не принимает параметров, инициализирует все поля пустыми значениями.

Поле класса:

`data: IBuyer` — данные, которые хранят:
`payment: TPayment` — выбранный способ оплаты. Принимает значения `'card'`, `'cash'` или `''` (не выбран).
`address: string` — адрес доставки покупателя.
`email: string` — электронная почта покупателя.
`phone: string` — номер телефона покупателя.

Методы класса:
`setData(newData: Partial<IBuyer>): void` — принимает объект типа `Partial<IBuyer>` и сохраняет переданные поля в модели, не затрагивая остальные поля, которые уже могут содержать значения. Позволяет обновить одно или несколько полей за один вызов.
`getData(): IBuyer` — возвращает объект со всеми данными покупателя типа `IBuyer`.
`clearData(): void` — сбрасывает все поля покупателя к исходным пустым значениям.
`validate(): Partial<Record<keyof IBuyer, string>>` — проверяет заполненность всех обязательных полей покупателя. Возвращает объект, в котором ключами являются названия полей с ошибками, а значениями — текст ошибки. Если поле заполнено корректно — оно в возвращаемом объекте отсутствует. Поле считается невалидным, если оно пустое.

### Слой коммуникации

#### Интерфейс IOrderData

Этот интерфейс описывает объект, который приложение получает с сервера или передаёт на него. Дополняет интерфейс IBuyer двумя полями:

`total: number` — сумма заказа.
`items: string[]` — список с айдишниками товаров.

#### Класс ProductAPI

Этот класс будет использовать композицию, чтобы выполнить запрос на сервер с помощью метода get класса Api и будет получать с сервера объект с массивом товаров.

`constructor(api: Api)` — получает Api

`getProducts(): Promise<IProduct[]>` — выполняет запрос на сервер с помощью метода get класса Api и получает с сервера объект с массивом товаров.

`createOrder(data: IOrderData): Promise<IOrderResponse>` — использует метод post класса Api, чтобы класс мог отправлять на сервер данные о покупателе и выбранных товарах.

### Слой представления

#### Класс Header

Отвечает за отображение шапки сайта.

Конструктор:
`constructor(container: HTMLElement, events: IEvents)`

Поля класса:
`counterElement: HTMLElement` — элемент счётчика товаров в корзине
`basketButton: HTMLButtonElement` — кнопка открытия корзины

Сеттеры:
`set counter(value: number)` — обновляет счётчик товаров

Генерируемые события:
`basket:open` — при клике на кнопку корзины

#### Класс Modal

Отвечает за отображение модального окна. Модальное окно не имеет дочерних классов — вся разметка внутри него является самостоятельными компонентами.

Конструктор:
`constructor(container: HTMLElement, events: IEvents)`

Поля класса:
`contentElement: HTMLElement` — контейнер для контента модалки
`button: HTMLButtonElement` — кнопка закрытия

Методы:
`open(): void` — открывает модалку, эмитит `modal:open`
`close(): void` — закрывает модалку, эмитит `modal:close`

Сеттеры:
`set content(value: HTMLElement)` — заменяет содержимое модалки

Генерируемые события:
`modal:open` — при открытии модального окна
`modal:close` — при закрытии модального окна

#### Класс CardPreview

Наследует Card. Карточка товара для детального просмотра в модалке.

Конструктор:
`constructor(container: HTMLElement, actions?: ICardActions)`

Поля класса:

#### Класс CardBasket

#### Класс Form (абстрактный)

### Презентер

Презентер реализован в файле `main.ts` без выделения в отдельный класс. Содержит всю логику связи между моделями данных и представлением через брокер событий.

#### Список событий

`catalog:changed` источник - Catalog - Каталог товаров обновлён  
`preview:changed` источник - Catalog - Выбран товар для просмотра  
`cart:changed` источник - Cart - Содержимое корзины изменилось
`buyer:changed` источник - Buyer - Данные покупателя изменились  
`card:select` источник - CardCatalog - Клик на карточку в галерее  
`basket:open` источник - Header - Клик на иконку корзины  
`order:open` источник - Basket - Клик на кнопку «Оформить»  
`order:submit` источник - FormOrder - Сабмит первой формы  
`contacts:submit` источник - FormContacts - Сабмит второй формы  
`form:changed` источник - Form - Изменение поля в форме  
`modal:open` источник - Modal - Модалка открыта  
`modal:close` источник - Modal - Модалка закрыта  
`success:close` источник - Success - Клик на кнопку закрытия успеха
